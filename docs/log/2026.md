#### The finding that reframed the batch

Three findings raised in three different sessions — **B2** (`normStat` threw),
**B7** (`validate` threw), **B6** (`migrate` left holes the engine threw
through) — were filed as unrelated items in two severity buckets. They are one
defect: **Decision 22 stated a contract and nothing enforced it.** Every time

So Batch 1 fixed the *class*. The contract is now written exactly — every
exported reader is total on anything `migrate()` returns — and a guard runs six
degenerate characters through twenty-seven readers, every `validate` step and
`skillLine`. **It found a fourth violation on its first run** (B10: an orphaned
skill id crashed the review screen, a case `versionCheck` explicitly reports as
supported). That is the argument for the guard, made by the guard.

#### What the CRB settled

`030_Core_Mechanics.docx` was read into the project for the first time, and it
closed **B3** in the opposite direction from the previous session's
recommendation. The engine reproduces both of the rulebook's worked examples
exactly — BOD 4 → 20 HP, and a Werewolf at BOD 11 → 10 HL × 6 HP = 60 HP — so
`levelsPerBOD` was redundant, not undecided. It also exposed **B8**: two floors
the CRB states plainly, sitting in the data as unread prose while the sheet
displayed bare penalties.

That produced **Mechanism 3**: `tests/rules.test.mjs`, where every assertion
quotes the CRB line it pins. **If that file and the CRB disagree, the CRB wins
and the file is the bug report.**

#### Verification, not assertion

- Every guard was **mutation-tested** against the pre-fix code. A guard that
  passes before and after is decoration.
- The data changes were proved inert by **diffing sixty computed outputs** —
  health at six BOD values, pain at four damage levels, milestones at ten MP
  totals — before and after. Byte-identical, which is why no version bumped
  (Decision 68 writes that rule down).
- B6's fix was checked against the original crash reproduction: all four paths
  that threw now return, `gamedataVersion` is *not* masked, and `versionCheck`
  still reports the mismatch.

#### Watch out for this

Writing regexes into test files through a shell heredoc **silently eats one
backslash level** — `\(` becomes `(`, a word boundary becomes a backspace
character. It bit three times this session and every failure looked like a
logic bug. Use the editor for anything containing escapes.

The data also lives in a **VM realm** (`loadEngine`), so its arrays carry another
`Array.prototype` and `deepStrictEqual` rejects them on identity alone. Spread
into a local array first. Both are noted in `rules.test.mjs`.

Do it before Batch 3 so the picks subsystem is authored under the copy standard

### 2026-09-03 — Batch 3: the selection & constraint system, and A3

Branch `feat/picks-system`. `npm run verify` ran before the first change (**58
passing, 1 todo, 0 failing**) and after every step; it closes at **77 passing, 0
todo, 0 failing** across six files. Decisions 77-81.

**The suite has no `todo` for the first time.** A1 was the last one and it had
been open since the rev 9 audit.

**What was built.** One selection system, hosted by three things — advantages,
disadvantages and skills. An entry declares `picks` (a fixed list, a category, or
free text), `excludes` (symmetric mutual lock) and `requires` (the milestone
prerequisite vocabulary, reused rather than reinvented); a character stores its
answers as `selections` on the entry that asked. Engine gains `optionLock`,
`requirementState`, `picksFor`, `setSelection`, `trimSelections` and the four
`specialization*` readers, all pure and all in the totality guard. `diffChar`
covers `selections` with no extra work, exactly as the audit predicted — checked
by reading `_walk`, not assumed.

All fifteen entries Decision 58 named are encoded, plus Martial Arts styles.

**Three judgement calls worth the ink.**

- **`grants` was split out** into Batch 3b. Decision 58 lists it beside `picks`,
  but they are not adjacent in the code: `picks` adds one reader and two
  validate hooks, while `grants` reaches into `skillPool`, `health`,
  `luckState`, `milestoneState` and a Natural Armor concept the engine does not
  have. Educated is the one that bites — bought at step 7, it grows the step-6
  pool retroactively, which is a wizard-flow ruling and not a data edit.
- **A3 needed no new data field.** The audit proposed `selectMode`. The Arcanist
  already carried `countBy`, and the other four archetypes carried nothing,
  which is "exactly one". Reading the silence was cheaper than editing five
  entries to state it.
- **No entry declares `excludes` or `requires`.** Ken asked for mutual locks and
  the machinery is built and tested, but the CRB names no pair, and writing one
  into the data to exercise the code would be resolving a rules question in
  code. Both are tested against a synthetic fixture pushed into the loaded data
  by the test and popped afterwards. It is on the Deighton list now.

**Two defects found in passing, neither looked for.**

- **A stale mirror.** Professional Natural Advantages live in
  `archetypeChoices.naturalAdvantages` and are mirrored into `ch.advantages`
  with `notes: "natural"`. Changing subtype cleared the ledger and left the
  mirror, so a player switching Cleaner → Enforcer silently kept the Cleaner's
  free advantages. Same two-parallel-models fault as A1/A2, one layer down.
  Fixed in the handler being rewritten anyway (Decision 81).
- **A guard that could not say "all clear".** `tests/docs.test.mjs` checks its
  own todo parser by looking for the `{ todo: }` sentinel anywhere in the test
  sources — and its own assertion *message* contains that sentinel. So the check
  could never pass at zero todos. It had been correct for as long as a todo
  existed, and broke the moment the suite got clean. Excluded from its own scan.
  This is the second time a guard in this file has validated its own blind spot;
  the first is recorded in Decision 74.

**And a third, smaller:** `package-lock.json` sat at `0.4.0` while the app said
`0.5.0`. `npm install` rewrites it from `package.json`, so the drift surfaced as
a stray diff rather than a failure. The version guard now checks both places the
lockfile states it.

**A trap that cost two debugging rounds, now written on the function that
causes it.** `loadEngine()` runs the engine in a `vm` context, so arrays it
returns carry that realm's `Array.prototype` and `assert.deepEqual` — strict, and
prototype-comparing — rejects them against a literal `[]`. The failure prints two
identical-looking empty arrays and says "not equal". The warning is on
`loadEngine()` itself now (Decision 80).

**Ten mutations, ten caught.** Every new guard was run against code with the fix
removed: re-rendering the aberration block, dropping `optionLock`'s reverse

and breaking the todo parser. All ten failed as they should.

**Versions.** App `0.5.0 → 0.6.0` (a player sees picks, locks, and one
specialization block where there were two). Game data `0.3 → 0.4` (fifteen
entries now demand an input they did not before — the Decision 68 test).
Character schema `0.4 → 0.5` (one specialization array replaces three fields,
with a `migrate()` step in the same commit). Ruleset unchanged.

**Deferred on purpose.** `src/ui/app.js` was **not** decomposed. STATE said to do
